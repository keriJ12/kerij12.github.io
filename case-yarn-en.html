Yarn Requirement Calculator — drop the order PDF, get kilograms per yarn

A single-file offline tool for production planning at an Austrian textile company: drop the customer's seasonal order PDF together with two Excel master files, and it recognises each file type, matches every order line to its article and colour, computes piece counts and kilograms for each warp and weft yarn, and exports a four-sheet Excel purchasing list. One governing rule: the number of yarns comes only from the article master, and missing values are never filled in. German UI with Chinese notes.

01Context

The setting

A seasonal order has dozens of lines, and each line means two to four yarns

The customer's order arrives as a PDF: each line names an article, a colour (Dessin) and a length in metres. Planning has to convert every line into weaving pieces, multiply by that article's warp and weft weight per piece, and only then knows how many kilograms of each yarn to buy. The article factors live in one Excel master, the yarn numbers per Dessin in another. This used to be done by looking up every line by hand.

Starting point

Like the sample annotator and the care-label composer: describe the tool in requirements

I do not write code, but I knew which three files the planner has, what is looked up at each step and where mistakes happen most. Say that clearly, let AI build it, test with real orders and fix what does not match. The tool was then used for one season's actual planning.

02Problem

Problem statement

The costly mistake is not a wrong kilogram figure — it is one yarn too many or too few

The colour master often fills the second warp field with the same number as the first; treating that as a second yarn doubles the quantity. Conversely, if the article master has a second weft factor and the colour master leaves it blank, skipping it halves the purchase. So the first rule is: how many yarns an article has is decided by the filled material rows of the article master; the colour master only supplies numbers; nothing missing is ever invented. That sentence appears in the code, the footer and the Chinese note.

Scope

Built — and deliberately not built

Built

  • Detect whether a dropped file is an order PDF, an article master or a colour master
  • Merge masters without overwriting; list conflicts between file and embedded values
  • Per line: pieces, two warp yarns, two weft yarns in kilograms
  • Totals per yarn number for warp and weft, with the lines they come from
  • Stamp check: does the sum of metres match the PDF total, how many lines lack master data
  • Excel export with four sheets, including which factors were used

Deliberately not built

  • Guessing any missing factor or yarn number
  • Borrowing a Dessin with the same number from another article
  • Order layouts of other customers
  • Stock deduction, purchase orders, version history

03Design decisions

Decision · Core

The number of yarns comes only from the article master

Only material rows with a weight (warp A/B, weft H/J) produce a yarn; when the colour master leaves B or J blank, the A or H number is reused. If the colour master names a B yarn but the article master has no B row, it is not counted — but it is listed in the control sheet for a human to check.

Decision · No guessing

A Dessin number that exists for another article is not borrowed

The same Dessin number can mean different yarns on different articles. When nothing matches, the tool says “this Dessin only exists for article X, not for this one — not used”, and leaves the decision to the planner.

Decision · Source of truth

Uploaded files win over embedded data, but differences stay visible

Embedded master data goes stale, so a newly dropped master file takes precedence. If a factor differs from the embedded value, the first control line says “file says X, previously Y, calculating with the file — please check”.

Decision · First glance

The stamp is either red or green

What the planner needs first is “can I use this?”. The stamp shows the number of lines, whether each order's metres add up to the PDF's stated total, and how many lines lack master data. Anything wrong turns the whole stamp red.

Decision · Mistakes that actually happened

Loading the same order twice is flagged red; a 0.5 m line is flagged as a placeholder

Both happened in real use: dropping an order twice doubled the quantities; the customer uses tiny-length lines as samples or placeholders that must not enter purchasing. The tool does not decide for the planner, but it makes sure they see it.

04How it works

Flow

Six stages, and the code is organised the same way

  • Read masters: sniff sheet labels to tell article master from colour master; derive the article number from the cell next to “Artikel”, from a number pattern, or from the sheet name.
  • Read the order PDF: take text coordinates, rebuild lines by y position, then regex the position lines, article number, colour, left/right side (which may sit in the article field or the colour field) and warnings.
  • Match and compute: pieces = metres ÷ warp length (the article's own, default otherwise); kg = weight per piece × pieces.
  • Sort and total: natural sort of yarn numbers, plain numbers first then prefixed families; line lists compressed to “3, 5–9, 14”.
  • Screen: Positions / Yarn totals / Control tabs plus the stamp.
  • Excel: frozen header, landscape print, group subtotals, missing-data rows highlighted, a fourth sheet listing the factors used and which were defaults.
Technology

One 4.5 MB file, fully offline

pdf.js, SheetJS and ExcelJS are embedded as base64 and decoded on load; the PDF worker runs from a Blob URL. Company PCs need no network and no installation. German number formats, Excel floats and article numbers hidden in sheet names are all handled. The hand-written code is about 36 KB.

Portfolio version

All data replaced by fiction, not a line of logic changed

Customer and company names removed; embedded master data replaced by 4 fictional articles and 10 Dessins chosen to cover “has a second warp”, “no second weft”, “no warp length”, “second yarn number differs from the first”. A “load demo order” button and a downloadable fictional order PDF (7 lines, including a left-side mark, a warning, one line whose Dessin does not exist and one 0.5 m placeholder) exercise the real PDF parsing path.

05Limits

Limits

It knows one customer's order layout, not PDFs in general

The position-line format and the “Artikel-Nr.” / “Farbe” labels are regular expressions written for one customer's purchase order; another customer means new patterns. Master parsing depends on the label text in the Excel files. It is a single-user local tool without version control or history. The original was used for one season of real planning; every figure in the portfolio version is fictional and represents no real article.
